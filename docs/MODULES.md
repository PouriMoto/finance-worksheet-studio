# ماژول‌های بعدی (نسخه‌ی Cloud) و نحوه‌ی اتصال

نسخه‌ی Local کامل است و هیچ بک‌اندی نمی‌خواهد. هر ماژول زیر جدا اضافه می‌شود و با یک پرچم در `packages/engine/src/features.ts` روشن می‌شود.
اتصال‌ها از قبل آماده‌اند: `Persistence` (store)، `SyncAdapter` (adapters)، `Features`، فیلدهای `access/tier` و `economy.yaml` با اعتبارسنج.

| ماژول | پرچم | وابسته به | نقطه‌ی اتصال |
|---|---|---|---|
| M1 حساب (OTP موبایل + Google) | `auth` | PocketBase | ورود در Layout؛ `setPersistence` سرور |
| M2 همگام‌سازی و تاریخچه | `sync` | M1 | `SyncAdapter` + `sessions/part_results` |
| M3 محتوای پولی امن | `paywall` | M1 | `forEdition('cloud')`، `part_content`، پلیر با fetch |
| M4 اشتراک و پرداخت | `paywall` | M3 | هوک‌های verify درگاه |
| M5 توکن و امتیاز | `tokens` | M3 | `economy.yaml` + `ledger` سرور |
| M6 کد تخفیف و کمپین | `coupons` | M4 | `coupons/campaigns/promotions` + زمان سرور |
| M7 خلاصه‌ی AI | `ai` | M1 + M5 | `ai_gateway` سرور (کلید فقط سمت سرور) |
| M8 PDF سرور | `serverPdf` | M1 | رندر Chromium با فونت وزیرمتن |
| M9 push/تلگرام | `push` | M1 | `enablePush` + سرور ارسال |

ترتیب پیشنهادی: M1 ← M2 ← M3 ← M4 ← M5 ← M6 ← M7 ← M8 ← M9. هر مرحله مستقل قابل‌انتشار است.

## تصمیم‌های ثبت‌شده برای ماژول‌ها
- **ورود:** هر دو: موبایل با OTP و حساب Google. PocketBase ورود OAuth2 با Google را پشتیبانی می‌کند؛ OTP موبایل را باید با هوک سفارشی و سرویس پیامک ساخت (OTP داخلی PocketBase ایمیلی است). دسترسی Google از ایران را تست کن.
- **پولی‌بودن بخش‌به‌بخش:** `access` در سطح پکیج و پارت (الان در اسکیما). برای رایگان‌کردن موقت یا کد تخفیف مخصوص یک بخش، مدل `promotions` سمت سرور:
  `target` (پکیج/پارت/تگ) + `type` (رایگان، درصد، مبلغ) + بازه یا قاعده‌ی دوره‌ای + کد اختیاری. دسترسی نهایی = پایه ∨ پروموشن رایگان فعال ∨ اشتراک ∨ توکن ∨ امتیاز. پیشنهاد: پروموشن رایگان فقط برای کاربر واردشده تا ثبت‌نام را بالا ببرد.
- **اقتصاد:** `content/economy.yaml` (مقادیر اولیه از منطق طراحی، نه داده‌ی واقعی؛ با داده‌ی استفاده تنظیم شود). قاعده‌های ضد سوءاستفاده در `npm run validate` اجباری‌اند.

## خلاصه‌ی AI (M7) — یافته‌های مهم
- **سهمیه‌ی رایگان Gemini مال «پروژه‌ی توسعه‌دهنده» است، نه حساب Google کاربر.** در مستندات، محدودیت‌ها per project هستند، نه per key و نه per user؛ پس ورود با Gmail سهمیه‌ی رایگان شخصی کاربر را در اپ تو فعال نمی‌کند.
- در سطح رایگان، پرامپت‌ها و پاسخ‌ها می‌توانند برای بهبود محصولات Google استفاده شوند، و برای کاربران EEA/UK/سوئیس باید پلن پولی باشد. سقف‌های دقیق رایگان دیگر در صفحه‌ی مستندات منتشر نمی‌شود و باید در کنسول AI Studio دید.
- نتیجه: کلید رایگان خودت برای **توسعه و آزمایش** خوب است، نه سرویس محصول. برای محصول از پلن پولی (کلید سرور) + اعتبار جداگانه برای کاربر استفاده کن.
- اگر کاربر کلید خودش را بیاورد (BYOK) سهمیه‌ی خودش استفاده می‌شود؛ این گزینه‌ی پیشرفته‌ی اختیاری است و نیاز به بررسی فنی (CORS، نگهداری امن کلید در مرورگر) دارد.
- ChatGPT (اشتراک مصرف‌کننده) API نیست؛ برای اتصال باید API جداگانه با صورت‌حساب جدا گرفت (تا جایی که می‌دانم). پیشنهاد: `ai_gateway` مستقل از ارائه‌دهنده (Gemini/OpenAI/Anthropic).
- حریم خصوصی: فقط خلاصه‌ی شواهد (باندها و شمارش‌ها) بدون شناسه‌ی شخصی ارسال شود؛ هدف‌ها و یادداشت‌ها فقط با رضایت صریح. خروجی با هش شواهد کش شود تا فشار دوباره‌ی دکمه بدون داده‌ی جدید هزینه نداشته باشد.
- هزینه: قیمت هر اعتبار = هزینه‌ی واقعی API هر خلاصه × ضریب سود؛ ثبت هزینه‌ی واقعی در `ai_summaries` و بازنگری ماهانه.

## PDF
- **امروز (Local):** صفحه‌ی `/me/report/` با دکمه‌ی «ذخیره به‌عنوان PDF» (چاپ مرورگر). فونت فارسی درست نمایش داده می‌شود و هیچ سروری لازم نیست.
- **بعداً (M8):** رندر سمت سرور با Chromium برای دانلود/ایمیل و گزارش برندشده.
